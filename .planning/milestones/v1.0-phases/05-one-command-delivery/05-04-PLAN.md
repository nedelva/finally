<objective>
Stand up the Playwright E2E harness and prove it end to end with one scenario, so every later spec
lands on infrastructure that is already known to run and known to fail loudly.

Purpose: PLAN.md section 12 requires E2E tests that exercise the **packaged container**, not the
source tree. A harness that runs but cannot report a failure is worse than none — it seals phases on
nothing. This plan therefore proves both directions: a passing suite exits 0, and a deliberately
failing spec exits non-zero.

Output: `test/package.json`, `test/package-lock.json`, `test/playwright.config.ts`,
`test/docker-compose.test.yml`, and `test/e2e/01-fresh-start.spec.ts`.

**The one command this phase standardises on** (copy it verbatim into every later gate):

`docker compose -f test/docker-compose.test.yml up --build --abort-on-container-exit --exit-code-from playwright`

`--exit-code-from playwright` is required, not optional. It pins *which* service's exit code the
command returns; without it, whichever container happens to abort first decides the exit status. A
synthetic two-service probe on this host (Compose v5.5.1) did propagate a non-zero code without the
flag, but that behaviour depends on ordering rather than on anything the compose file declares, so
the pinned form is what ships. `--exit-code-from` implies `--abort-on-container-exit`; both are kept
for readability.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| npm registry → `test/node_modules` and the container image | Third-party code is fetched and executed by the test runner; a substituted or typosquatted package runs with full access to the test environment |
| compose network → host network | Anything the `app` service publishes with `ports:` becomes reachable from outside the test run |
| committed spec/compose files → version control | Any credential written into these files is permanently in git history |
