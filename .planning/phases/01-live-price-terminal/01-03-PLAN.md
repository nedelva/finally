Author `backend/tests/market/test_stream.py` following the conventions of `tests/market/test_simulator_source.py`: a module docstring, one `TestSSEStream` class, short single-behaviour async methods. The mechanism is new to this project — an `httpx.AsyncClient` over `httpx.ASGITransport` wrapping a `FastAPI` instance that mounts the router under test, then `client.stream` plus `aiter_lines`, iterating until the line of interest and then breaking out. Keep every streaming test bounded. The generator loops forever by design, so each test must break out of `aiter_lines` on the line it is looking for and must cap how many lines it will read before failing — an unbounded `async for` that never finds its line turns a failed assertion into a hung suite.

Cover the behaviours listed above. Three of them need specific construction:

*Router isolation.* Build two separate `PriceCache` instances, populate the first with AAPL only and the second with TSLA only, and call `create_stream_router` once per cache. Assert the two returned objects are not the same object and that each carries exactly one route. Then mount each on its own `FastAPI` app and stream both, asserting the first app's data frame contains AAPL and does not contain TSLA, and the converse for the second. This is the behavioural form of the module-level-singleton defect, and it is a better test than inspecting where the router object is constructed.

*Empty-cache version gating.* This one needs a stub rather than a real cache, because a real `PriceCache` cannot advance its version without gaining contents, and the defect is precisely about a version generation being consumed by an empty read. Write a small test-local stub class exposing the two members the generator actually touches: a `version` property that returns a fixed value such as 1, and a `get_all()` that returns an empty dict on its first call and a dict containing one real `PriceUpdate` on every call after that. Stream from a router built over the stub and assert a `data:` frame containing that ticker arrives. Against the current code this test fails: the first cycle sees version 1 differing from the initial sentinel, advances its bookkeeping to 1, reads empty, sends nothing — and every later cycle now sees version 1 matching its bookkeeping and never reads again, so the frame never arrives and the read cap trips. Against the fixed code the bookkeeping is not advanced by the empty read, so the second cycle reads again and delivers. Run this test before touching `stream.py` and confirm it is red for that reason.

*Keepalive.* The interval must be injectable or the test would have to wait fifteen seconds. Populate a cache once so its version stops changing, build the router with a short keepalive interval, stream, and assert a line starting with a colon arrives after the initial retry directive and any data frame.

Now make the three changes in `backend/app/market/stream.py`.

Change one — construct the router per call. Move the `APIRouter` construction out of module scope and into the body of `create_stream_router`, keeping the same prefix and tags, so every call returns a fresh instance rather than decorating a shared object. This is CONVENTIONS.md's factory rule, which the function's own docstring already claims to follow while doing the opposite. Delete the module-scope binding entirely rather than leaving it in place unused.

Change two — gate the version bookkeeping on non-empty contents. Today the generator reads the version, immediately records it as seen, then reads the contents and only sends if they are non-empty. Restructure so the recording of the version happens inside the non-empty branch, after the contents have been read and found to have entries. The read of the version and the comparison against the last-seen value stay where they are; only the assignment moves inward.

Change three — add keepalive comments. Extend the generator's signature with a keyword-only `keepalive_interval` float defaulting to 15.0, and extend `create_stream_router` with keyword-only `interval` and `keepalive_interval` parameters carrying the same defaults the generator already uses, passing them through. Defaults must leave `backend/app/main.py`'s existing single-argument call working untouched. Inside the generator, track the time of the last emitted line using `time.monotonic()`, and when that much time has elapsed without anything being sent, yield a comment line — a colon, a short label, and the SSE double-newline terminator — and reset the marker. Reset the marker on data frames too, so keepalives are only emitted during genuine silence. A comment line is ignored by the browser's `EventSource` but keeps an intermediary from treating the connection as dead; CONCERNS.md notes this matters under the Massive source's fifteen-second poll interval and is invisible under the simulator's 500ms cadence.

Preserve exactly, in all three changes: the retry directive as the first thing yielded; the `data:` framing with a JSON payload and the double-newline terminator; the disconnect check via the request's `is_disconnected`, the `asyncio.CancelledError` handler, and the connect and disconnect log lines with their percent-style formatting; and the response headers for cache control, connection keep-alive, and proxy buffering. Do not change the media type. Do not add a concurrent-connection limit — CONCERNS.md records that as a knowingly deferred scaling limit for a single-user demo, and it is not in this phase's scope.
