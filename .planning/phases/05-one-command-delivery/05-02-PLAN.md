<objective>
Give the operator a lifecycle they cannot break: start, stop, start again, as many times as they
like, with their portfolio, watchlist, and chat history intact every time.

repeatedly with no duplicate containers, no error on a second stop, and no path by which stopping
destroys data. This is the half of OPS-02 that plan 05-01's tracer could not reach, because the
tracer never stopped and restarted anything.

Output: four idempotent operator scripts, a convenience `docker-compose.yml`, a README section, and
a real restart-persistence proof.
</objective>

exactly the transparency failure this plan prohibits. If the poll times out, print a diagnostic
pointing at `docker logs finally` and exit non-zero.

do not enable shell tracing; the operator's API keys must not reach the terminal or a CI log.

recreates the named data store `finally-data`, and must pass no flag that discards attached storage

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| root `.env` → operator terminal / CI log | The scripts handle a file containing live API keys; anything they print crosses into logs the operator may share |
| operator command → persisted database | A single destructive flag in a routinely-run script is the difference between a stop and a data loss |
| host port 8000 → local network | Publishing the app binds a host port for as long as the container runs |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-05 | Information Disclosure | `scripts/*` handling of the root `.env` | medium | mitigate | The scripts reference `.env` by path via `--env-file` and never read, source, print, or interpolate its values; no script enables shell tracing. Asserted by acceptance criteria requiring the absence of `set -x` and of any read of the file's contents. |
| T-05-06 | Denial of Service | `scripts/stop_mac.sh`, `scripts/stop_windows.ps1` | high | mitigate | Both stop scripts act on the container only. A grep over their non-comment lines asserts they match none of the destructive storage patterns, so a stop cannot delete the operator's trades, watchlist, or chat history. Verified by an automated check in Tasks 1 and 2 and by the round-trip persistence assertion in Task 1. |
| T-05-13 | Spoofing | host port 8000 binding | low | accept | `-p 8000:8000` binds all host interfaces, matching PLAN.md section 11's documented invocation verbatim. Accepted rather than narrowed to `127.0.0.1:8000`: the locked spec's `docker run` line is what the README already publishes and what an operator will copy, and this is an unauthenticated single-user local tool by design (REQUIREMENTS.md "no auth" is explicitly out of scope). Narrowing the binding would silently diverge the scripts from the documented command. |
| T-05-01 | Information Disclosure | `docker-compose.yml` `env_file` | high | mitigate | Secrets reach the container only at run time through `env_file: [.env]`; `.env` is gitignored and excluded by `.dockerignore`, so it never enters an image layer. Inherited control from plan 05-01. |
