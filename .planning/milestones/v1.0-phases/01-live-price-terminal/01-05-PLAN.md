<objective>
**As a** user of FinAlly, **I want to** click any ticker to pull its price history up as a full chart, and see at a glance from the header whether my price feed is actually live, **so that** I can trust what I am looking at and drill into whichever symbol I care about.

The connection dot is the only thing that tells a user whether the terminal is streaming or frozen — without it, a dropped stream looks identical to a quiet market. The main chart area turns the watchlist from a read-only ticker tape into something navigable.

`frontend/components/ConnectionDot.tsx` — a client component. Export `ConnectionDot`, taking a required status of the `ConnectionStatus` type imported from `frontend/lib/types.ts`; import that union rather than writing a local one, so the component's input domain cannot drift from the hook that produces it. Render a small round element whose colour is chosen from the status: the up-colour token for connected, the accent-yellow token for both connecting and reconnecting, and the down-colour token for disconnected. Amber is correct for both of the in-flight states, because from the user's point of view "opening for the first time" and "retrying after a drop" are the same situation — not yet live, not yet given up on.

Expose the state two ways beyond colour. Put the raw status string on a `data-status` attribute, which is what the tests assert against so they do not couple to utility class names. And give the element an `aria-label` naming the state in words, because a colour-only indicator conveys nothing to a screen reader or to a colour-blind user, and this is the sole signal in the entire interface that distinguishes a live stream from a frozen one. Render a short status label as visible text next to the dot as well.

Add a subtle pulse to the amber states only, so "retrying" reads as activity rather than a steady warning. Use a CSS animation utility for it; do not drive it from a JavaScript timer.

`frontend/components/Header.tsx` — a client component. Export `Header`, taking the stream status. Render a compact bar using the panel and border theme tokens: the brand text `FinAlly` on the left with a short descriptor, and the connection dot on the right. Carry the literal disclosure text stating that the market data is simulated — the header is the most authoritative-looking surface in the terminal, and this is where a user's eye settles when deciding whether to trust a number. The disclosure may live here rather than in the page body; the invariant asserted by the build grep is that it renders somewhere in the served HTML.

Show no portfolio total value and no cash balance. PLAN.md section 10 lists both as header content, and they are deliberately absent here: they are PORT-01 in Phase 3, which is the phase that introduces the database and the portfolio. Do not stand them in with a fixed figure, a zero, or a dash-filled slot styled to look implemented — a header showing a hardcoded ten thousand dollars would read as a working portfolio to the user and to the next planner. Leave the space for them and add them when the data exists.

Do not add any reconnection logic anywhere in this task. The native `EventSource` already retries on its own schedule using the `retry: 1000` directive the server emits, plan 01-02's hook already translates its open and error events into status values, and this component's only job is to display the value it is handed. A hand-rolled backoff loop would fight the browser's own retry and is explicitly called out in RESEARCH.md's "Don't Hand-Roll" table.

`frontend/app/page.tsx` — render `Header` above the watchlist, passing the status from the stream context. Keep the provider placement from plan 01-02 unchanged.
