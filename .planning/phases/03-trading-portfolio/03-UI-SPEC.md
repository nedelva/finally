## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | none — hand-rolled Tailwind v4 components (`frontend/components/*.tsx`), established in Phases 1–2 |
| Icon library | none — text/unicode glyphs only (e.g. `×` remove button, `…` loading ellipsis), matching existing convention |
| Font | system default sans-serif stack (Tailwind's default `font-sans`); no custom font loaded via `next/font` |

**Default applied without asking (shadcn gate):** `components.json` is absent and the stack is Next.js, which would normally trigger the shadcn-initialization question. Skipped here because Phases 1–2 already shipped two complete phases of hand-rolled Tailwind components (Watchlist, WatchlistRow, MainChart, Header, ConnectionDot, Sparkline) with an established CSS-custom-property theme (`app/globals.css`). Introducing a component library mid-project would fragment the visual system this phase must extend, not replace. If this default is wrong, override before planning proceeds.

`recharts` (3.10.1) is already an installed frontend dependency (used by `MainChart`) and is reused for the new P&L line chart and the heatmap's `Treemap` component per CONTEXT.md D-09 — no new charting library needed.

**Verified, not recalled:** `grep -n "Treemap" frontend/node_modules/recharts/types/index.d.ts` — `recharts@3.10.1` (2026-09-20) confirms `export { Treemap } from './chart/Treemap'` at the package's top-level entry point. D-09's premise holds; no substitute library is needed for PORT-05.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px | 400 | 1.5 |
| Label | 12px | 500 | 1.4 |
| Heading | 16px | 600 | 1.3 |
| Display | 20px | 600 | 1.2 |

**Established exception to the 2-weight guideline:** three weights (400/500/600) are already in shipped Phase 1–2 code — 400 for body/table-cell text, 500 (`font-medium`) for table headers and panel sub-headings, 600 (`font-semibold`) for the app title, primary buttons, and emphasized values (e.g. selected ticker symbol). This phase reuses all three rather than consolidating to two or introducing a fourth.

Usage map for new Phase 3 surfaces:
- Body (14/400): positions-table cell values, trade-bar input text, chat-style inline fill confirmation.
- Label (12/500, uppercase, `tracking-wide`, `text-gray-500`): positions-table column headers, heatmap/P&L-chart panel captions, axis ticks.
- Heading (16/600, `tabular-nums`): the new header cash-balance figure and total-portfolio-value figure (PORT-01) — sits beside the existing 20/600 "FinAlly" wordmark without competing with it; also used for panel section titles ("Positions", "Portfolio Heatmap", "P&L"), matching `MainChart`'s selected-ticker treatment.
- Display (20/600): unchanged — reserved for the "FinAlly" wordmark only (`Header.tsx`).

### Header cash & total value (PORT-01)

`Header.tsx`'s Phase 1 comment is explicit that this header must show no dollar figure at all until Phase 3, and never a placeholder zero/dash styled to look implemented. This phase fills that hole:

| Aspect | Spec |
|--------|------|
| Typography | Heading role (16px/600, `tabular-nums`) for both the cash-balance and total-value figures — visually distinct from the 20/600 wordmark, consistent with numeric emphasis elsewhere (e.g. `MainChart`'s selected-ticker price) |
| Color | Neutral `text-gray-100` (matching existing watchlist price-cell color) for both figures — **not** up/down semantic color. Total value moving above/below the $10,000 cost basis is not flagged green/red in the header; that judgment stays in the positions table and heatmap, which already carry per-position P&L color. Keeping the header neutral avoids a second, competing color signal for the same underlying number. |
| Flash behavior | **Explicitly no price-flash animation** on either header figure, even though total value recomputes on every SSE tick (~500ms). `usePriceFlash` stays scoped to watchlist rows; wiring it to the header would strobe continuously as the underlying prices tick. This is a deliberate prohibition, not an oversight. |
| Loading | Before the first `GET /api/portfolio` resolves: render `$10,000.00` is **not** assumed — show a loading placeholder (e.g. `—` em dash, matching `formatMoney`'s existing null-safe fallback) rather than a styled zero, satisfying the Phase 1 comment's prohibition. |
| Error | If the initial portfolio fetch fails, the header shows the same `—` fallback (not a thrown error or blank header) — the connection-status dot already signals stream health; the header does not duplicate a second error indicator for this. |
| Live update | Total value recomputes from the SSE price stream via the same `deriveLivePosition` math already in `positionMath.ts` — no separate polling loop. |

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#0d1117` (`--color-bg`) | Page background |
| Secondary (30%) | `#161b22` (`--color-panel`) / `#30363d` (`--color-border`) | Panel backgrounds, table/card borders, chrome |
| Accent — Brand | `#ecad0a` (`--color-accent-yellow`) | App wordmark ("FinAlly" title) only — not extended to any Phase 3 element |
| Accent — Primary | `#209dd7` (`--color-primary-blue`) | Chart line stroke (MainChart + new P&L chart), focus rings, selected-row/selected-tile highlight tint |
| Accent — CTA | `#753991` (`--color-secondary-purple`) | Existing neutral submit buttons only (e.g. "Add Ticker"); no new purple buttons introduced this phase |
| Positive semantic | `#16a34a` (`--color-up`) | Buy button fill, uptick price flash, positive unrealized P&L text, profit-colored heatmap tiles |
| Destructive/negative semantic | `#dc2626` (`--color-down`) | Sell button fill, remove-ticker button, downtick price flash, negative unrealized P&L text, loss-colored heatmap tiles, all error-slot text |

Accent reserved for: yellow → wordmark only; blue → chart line stroke, input focus ring, selected-state background tint; purple → the existing "Add Ticker" submit button (no new use this phase). **Design decision (not pre-specified in CONTEXT.md):** the trade bar's Buy and Sell buttons use the positive/negative semantic colors (`--color-up` / `--color-down`) as solid fills — matching finance-convention buy=green/sell=red and reusing colors already load-bearing for price direction and P&L, rather than overloading the brand accent (purple) for two opposite actions that need to stay visually distinct from each other.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA — Buy | "Buy" (noun supplied by the adjacent ticker dropdown + quantity field, mirroring the existing compact trade-bar layout; PLAN.md §10 specifies "buy button, sell button") |
| Primary CTA — Sell | "Sell" |
| Empty state heading (positions table & heatmap) | "No positions yet" |
| Empty state body (positions table & heatmap) | "Buy a ticker to see it here." (verbatim per CONTEXT.md D-11 for the heatmap; reused for the positions table's empty state for consistency — not separately discussed, flagged below) |
| Error state — insufficient cash (buy) | "Insufficient cash for this trade. Lower the quantity and try again." |
| Error state — insufficient shares (sell) | "You don't own enough shares to sell that many. Lower the quantity and try again." |
| Trade fill confirmation — buy | "Bought {quantity} {ticker} @ ${price}" — e.g. "Bought 2 AAPL @ $190.32" (verbatim per CONTEXT.md D-07) |
| Trade fill confirmation — sell | "Sold {quantity} {ticker} @ ${price}" — e.g. "Sold 1.5 NVDA @ $812.10" (verbatim per CONTEXT.md D-07) |
| Trade bar disabled hint (empty watchlist) | "Add a ticker to your watchlist to start trading." |
| Destructive confirmation | None — trades execute instantly with no confirmation dialog, per PLAN.md §2/§9 and the project's explicit Out-of-Scope list. Sell is not treated as a destructive action requiring a confirmation step. |
