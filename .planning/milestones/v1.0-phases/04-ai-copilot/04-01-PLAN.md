<objective>
**As a** FinAlly user, **I want to** ask the assistant about my portfolio in plain language and get
an answer that quotes my actual cash, holdings and watchlist prices, **so that** the terminal can
explain itself to me instead of making me read six panels.

This is the phase's tracer slice: the thinnest path that touches every layer Phase 4 will modify —
browser component, REST client, FastAPI route, prompt assembly, the LiteLLM call, and a SQLite
write — wired end-to-end and proven by a real integration test through the running ASGI app. Later
plans expand outward from this spine: 04-02 adds action execution to the same route and the same
panel, 04-03 adds history rehydration to the same panel. No action execution lands here: the
assistant can read the portfolio and talk about it, but cannot yet act on it.

Purpose: CHAT-01 and CHAT-02 are the load-bearing half of the phase — every later requirement is a
variation on a working, grounded round-trip. Getting the prompt context wired to the *existing*
build_portfolio / build_watchlist functions early is what guarantees the assistant can never quote a
number the rest of the terminal disagrees with.

Output: `POST /api/chat`, the `app/llm` package behind it, chat-message persistence, and a working
AI Copilot panel docked in the terminal.
</objective>

  `SYSTEM_PROMPT` must establish, as prose the model reads:
  - Identity: FinAlly, an AI trading assistant inside a simulated-money trading terminal.
  - Voice (D-04): a terse desk analyst — short, numbers-first sentences, minimal pleasantries. No
    filler openers, no restating the question back.
  - Capabilities: it can analyse portfolio composition, concentration and P&L, and it can request
    trades and watchlist changes, which the server executes.
  - Action policy (D-05): only emit a trade when the user's own message asks for that specific
    trade, or clearly agrees to a trade the assistant proposed in an earlier turn. Never propose an
    action and execute it in the same turn. Suggesting without executing is the correct behaviour
    when the user has not asked.
  - Action policy uniformity (D-06): the same rule governs watchlist changes. There is no looser
    rule for watchlist edits on the grounds that they carry no financial risk.
  - Output: always valid JSON matching the provided schema, with `trades` and `watchlist_changes`
    as empty arrays when no action is warranted.

  `render_portfolio_context` takes the dicts returned by `build_portfolio` and `build_watchlist` and
  renders one plain-text block containing: cash balance, total value, total unrealized P&L, one line
  per position (ticker, quantity, avg cost, current price, unrealized P&L and percent), and one line
  per watchlist entry (ticker plus live price, with an explicit no-price marker when `price` is
