<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → `POST /api/watchlist` | Untrusted user-supplied ticker string crosses into the process — the primary untrusted input of this phase |
| `app/api` → `app/db` | The submitted value crosses into SQL statement execution |
| `app/api` → `MarketDataSource` | The submitted value becomes a dict key and, on the Massive path, part of an outbound API request |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-05 | Tampering | `add_watchlist_ticker` SQL | high | mitigate | The inserted ticker is bound as a `?` placeholder parameter, never interpolated into SQL text. Enforced by the `ruff check --select S608` gate on Task 1. |
| T-02-06 | Denial of Service | unbounded ticker string | medium | mitigate | `is_valid_ticker_format` rejects anything outside `[A-Z0-9]{1,5}` before the value reaches the database, `PriceCache`, or either data source — so no oversized string becomes a row, a dict key, or log spam. Task 1 asserts the over-length case returns 400 with no write. |
| T-02-07 | Tampering | ticker used in an outbound Massive request | medium | mitigate | The same 1-5 alphanumeric gate runs before any notify, so no injected or control-character payload can reach the upstream client. |
| T-02-08 | Spoofing | none applicable | low | accept | Single-user app, no auth, no sessions — PLAN.md §7 scopes all rows to `user_id="default"`. ASVS V2/V3/V4 do not apply. |

Package legitimacy: not applicable — this plan installs nothing.
