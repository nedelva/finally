<objective>
**As a** FinAlly user, **I want to** reload the terminal and still see the conversation I was
having, **so that** my assistant remembers what we already discussed instead of greeting me like a
stranger every time I refresh.

This plan closes the half of CHAT-06 that persistence alone does not solve. 04-01 already writes
every turn to `chat_messages`, but nothing reads them back — `POST /api/chat`'s response only ever
carries the new turn, and `PLAN.md` section 8's endpoint table has no chat-history `GET` at all.
This adds the missing endpoint and hydrates the panel from it on mount.

Purpose: CHAT-06 is the last requirement in the phase and the one most likely to be mistaken for
done. 04-RESEARCH.md Pitfall 5 documents a prior implementation of this exact feature that persisted
every turn faithfully and still lost the visible conversation on reload, because the panel always
seeded a greeting and never fetched.

Output: `GET /api/chat/history`, the repository read behind it, the frontend type / fetch / hook
trio, and a chat panel that rehydrates itself.
</objective>
